# User authentication implementation checklist

Work through the tasks in order. The numbers in each link identify a requirement and its acceptance criteria.

- [ ] **1. Create the account and identity tables.** Enforce unique email and provider-subject keys. Verify that concurrent registrations for one email create one account. [Requirements 1.1, 1.4](1-requirements.md#requirement-1-user-registration)
- [ ] **2. Implement password validation and hashing.** Test length, character classes and a breached password using a local lookup fixture. Verify the stored bcrypt cost is 12. [Requirements 7.1, 7.3 to 7.5](1-requirements.md#requirement-7-password-security)
- [ ] **3. Implement registration.** Return field errors for malformed input and a reset suggestion for a duplicate email. [Requirements 1.1 to 1.4](1-requirements.md#requirement-1-user-registration), [10.2 to 10.3](1-requirements.md#requirement-10-error-handling-and-user-feedback)
- [ ] **4. Add email verification.** Capture the verification email in a test mailbox. Follow the link and check the verified state. Advance the clock 24 hours on a second account and check its pending state. [Requirements 1.5 to 1.6](1-requirements.md#requirement-1-user-registration)
- [ ] **5. Issue and validate access JWTs.** Check the ID, email and role claims. Advance the clock 15 minutes and expect HTTP 401. [Requirements 5.1 to 5.4](1-requirements.md#requirement-5-jwt-token-management)
- [ ] **6. Implement password login.** Verify successful token issuance, identical errors for unknown users and wrong passwords, and the reminders for unverified and locked accounts. [Requirements 2.1 to 2.5](1-requirements.md#requirement-2-emailpassword-authentication)
- [ ] **7. Add refresh and logout.** Verify seven-day expiry. Submit the same refresh credential twice concurrently and assert one rotation succeeds. Log out and confirm the replacement is revoked. [Requirements 5.3, 5.5 to 5.7](1-requirements.md#requirement-5-jwt-token-management)
- [ ] **8. Implement Google and GitHub authorization.** Use provider stubs to check each redirect, callback state validation and code exchange. [Requirements 3.1 to 3.3](1-requirements.md#requirement-3-oauth-20-authentication)
- [ ] **9. Resolve and link provider identities.** Test new and returning identities, then a matching email on a password account. Check that linking requires confirmation from the authenticated account owner. [Requirements 3.4 to 3.6](1-requirements.md#requirement-3-oauth-20-authentication)
- [ ] **10. Issue reset links.** Capture two emails in sequence and verify that only the latest link opens the reset form. [Requirements 4.1, 4.2, 4.6](1-requirements.md#requirement-4-password-reset)
- [ ] **11. Complete password resets.** Test expiry after one hour, password policy, single use and confirmation email. Verify the old password fails. [Requirements 4.3 to 4.5](1-requirements.md#requirement-4-password-reset)
- [ ] **12. Enforce account and IP limits.** Test the fifth and sixth failures for one account, the twentieth and twenty-first for one IP, automatic unlock and the counter reset on successful login. [Requirements 6.1 to 6.4, 6.6](1-requirements.md#requirement-6-rate-limiting-and-brute-force-protection)
- [ ] **13. Limit reset requests.** Verify that the fourth request in an hour returns the retry time and queues no email. [Requirement 6.5](1-requirements.md#requirement-6-rate-limiting-and-brute-force-protection), [10.5](1-requirements.md#requirement-10-error-handling-and-user-feedback)
- [ ] **14. Expose session management.** List device, location and last activity. Test revoking one session and revoking all others. Verify another user's sessions are inaccessible. [Requirements 8.1 to 8.4](1-requirements.md#requirement-8-session-management)
- [ ] **15. Revoke sessions on password changes.** Change a password while signed in from two devices. Verify that only the current device can refresh. [Requirement 7.6](1-requirements.md#requirement-7-password-security), [8.5](1-requirements.md#requirement-8-session-management)
- [ ] **16. Record events and deliver alerts.** Check login audit fields, provider failure details, signature mismatch events, suspicious activity alerts and lockout email using local sinks. [Requirement 2.6](1-requirements.md#requirement-2-emailpassword-authentication), [9.1 to 9.5](1-requirements.md#requirement-9-security-logging-and-monitoring)
- [ ] **17. Enforce HTTPS and cookie protections.** Verify that credentials travel over TLS and that the refresh cookie carries the Secure and HttpOnly flags. [Requirement 7.2](1-requirements.md#requirement-7-password-security)
- [ ] **18. Verify public errors end to end.** Exercise invalid credentials, duplicate registration, invalid fields, an internal failure and throttling. Check each response and verify the internal diagnostic appears only in the service log. [Requirements 10.1 to 10.5](1-requirements.md#requirement-10-error-handling-and-user-feedback)
